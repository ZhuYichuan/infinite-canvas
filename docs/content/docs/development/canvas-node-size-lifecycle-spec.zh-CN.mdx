# 画布节点全模态尺寸生命周期与无抖动占位规范 (Spec)

## Problem Statement

在当前无限画布系统中，用户在创建节点、提交生成任务（如文生图、图生图、文生视频）及等待结果返回的过程中，遭遇了严重的**节点外框尺寸突变、自动收缩与画面布局抖动**，造成了极大的使用困扰：

1. **初始规格与主流模型严重错位**：
   - 图片节点在创建时被硬编码为偏小横版框（`340px × 240px`，比例约 1.417）；
   - 现代主流生图模型默认输出均为 1:1 正方形（如 1024×1024）；在旧有的结算约束下，正方形图片被高 240 截断，宽度被迫连带缩到 240px。节点从 340 宽瞬间骤降 100px 至 240px，卡片极度局促。
2. **生成占位（Loading 态）与最终产物脱节**：
   - 任务在生成等待期间，占位卡片始终呈现为 `340px × 240px` 的横版外框；
   - 任务一旦完成，回调函数强制根据图片像素内切，如果是 9:16 竖图，卡片会从 340px 暴跌到 135px（宽度萎缩逾 60%）；
   - 尺寸突变伴随着节点重新计算几何中心坐标，导致四周向内坍缩，底部的提示词输入面板（Prompt Panel）向上弹跳，悬浮工具栏发生位移，连线端点剧烈晃动。
3. **用户手动排版意图被强制抹除**：
   - 若用户在生成前手动拖拉手柄拉大节点（例如拖至 `600px × 600px` 希望获得大图预览效果），生成完成回调仍死板调用 `fitNodeSize(..., 340, 240)`，用户精心拉大的节点被强制重置回微缩尺寸。
4. **派生节点忽略上游配置**：
   - 从配置节点（Config Node）或文本节点连线派生新图片时，派生节点未读取上游已经指定的目标比例，依然以 `340×240` 落地，导致“创建-提交-完成”全流程反复变形。
5. **模态与来源尺寸标准割裂**：
   - 用户从本地粘贴或上传图片，最大边被分配为 `640px`；超分节点也采用 `640px`；而 AI 生图结果却被圈禁在 `340×240` 框内，视觉体量严重失衡。

---

## Solution

建立统一的**画布节点全模态尺寸生命周期契约（Canvas Node Sizing Lifecycle Contract）**，从根本上终结“先横框、再缩水、来回抖”的体验缺陷：

```
[ 阶段 1: 节点落子 ]
  - 静态创建: 根据当前生效配置 (AiConfig.size) 精确计算比例落子 (默认 420×420 基准)
  - 动态派生: 从上游配置节点/文本节点连线派生时，继承来源配置的目标比例
  - 图生图: 优先继承首张参考图的原始比例 (naturalWidth / naturalHeight)
        │
        ▼
[ 阶段 2: 任务提交 (Loading 骨架屏) ]
  - 空白节点提交: 骨架屏外框在提交瞬间立即就绪为目标比例
  - 用户手动拉大的空白节点: 锁定当前拉大尺寸，绝对禁止重置
  - 已有素材节点再次生成 (Repeat): 原老节点 100% 保持不动，在右侧派生全新节点，按新配置比例初始化 420px 基线骨架
        │
        ▼
[ 阶段 3: 结果返回与结算 ]
  - 外框绝对静止 (Lock Outer Frame): 骨架屏外框不再发生任何像素级变形
  - 内部图像自适应: 微小像素差异 (如潜空间 8 像素对齐) 由内部 object-contain 吸收
  - 底部工具栏与输入面板保持绝对静止，零抖动呈现最终画面
```

## User Stories

1. 作为画布创作者，我在顶部工具栏或快捷键创建空白图片节点时，希望卡片落地时的宽高比直接匹配我当前配置的偏好比例（如 1:1 为 `420×420`，16:9 为 `420×236`），以便从创建第一秒就获得符合最终预期的视觉占位。
2. 作为画布创作者，我在从配置节点（Config Node）发起生图任务时，希望新建的图片占位卡片能够直接继承配置节点中设定的尺寸比例，以便在生成过程中不会看到无关的横版占位框。
3. 作为画布创作者，在发起图生图（Img2Img）或风格迁移任务且未显式锁定输出尺寸时，我希望目标图片节点自动继承参考图的宽高比，以便生成出来的卡片与原素材保持和谐的视觉比例。
4. 作为画布创作者，当我在生成前手动拖拉手柄把节点拉大至自定义尺寸时，我希望任务完成后节点依然保持我设定的尺寸，以便让我自主掌控画面在画布中的主次排版。
5. 作为画布创作者，当 AI 生成任务完成、图片下载呈现时，我希望节点的外框保持绝对静止，以便底部的提示词输入框、上方悬浮工具栏和左右连线端点不会发生任何位移跳跃。
6. 作为画布创作者，当后端工作流因潜空间 8 像素或 64 像素对齐产生细微长宽差异时，我希望节点外框不变，由内部画面以等比无裁切方式居中展示，以便杜绝 2~5 像素级别的界面微抖动。
7. 作为画布创作者，当我对一张已经生成完毕的卡片调整参数并点击“再次生成”时，我希望原老节点 100% 保持不动，并在右侧派生一个以新配置比例为基准的新节点，以便我既能安全保留已有的成果资产，又能在新卡片上尝试新的尺寸与创意。
8. 作为画布创作者，当我在多图批次（Count > 1）生成中切换主图（Set as Primary）时，我希望节点外框保持稳定，以便不同批次图片在切换预览时不会让节点忽大忽小。
9. 作为画布创作者，当我展开多图批次卡片（Batch Expanded）时，我希望网格中陈列的每一个子图片卡片与主卡片保持一致的比例，以便获得工整的多候选预览画廊。
10. 作为画布创作者，当我在已有图片节点上点击“超分放大（Upscale）”生成高清图时，我希望衍生的子节点体量与父节点保持同级对齐，以便避免突兀产生一张填满屏幕的巨幅卡片。
11. 作为画布创作者，当我在已有图片节点上进行“局部裁剪（Crop）”时，我希望裁剪出来的子节点最大边与原节点相称，以便派生流向清晰自然。
12. 作为画布创作者，当我在节点底部设置面板中主动切换比例（例如从 1:1 改选为 9:16）时，我希望节点以几何中心为锚点平滑变形，以便视觉重心留在原地，同时输入面板自然吸附在底部。
13. 作为画布创作者，在使用文生视频与全能视频节点时，我希望视频卡片同样遵循“提前按比例占位、生成完成外框冻结”的规则，以便视频与图片节点拥有高度统一的操作直觉。
14. 作为画布创作者，当生成任务失败进入错误状态时，我希望错误提示在既有尺寸框内优雅呈现，且外框不发生形变缩水，以便点击重试时能无缝接续。
15. 作为协同画布用户，当远程协作者发起生成并产生新图片时，我希望在视口中看到的是平滑填充的图像，而不是看到卡片在远端忽大忽小地跳动。

## Implementation Decisions

### 1. 规范核心基准与几何度量引擎

- **统一最大基准外框**：
  - 将图像与视频节点的默认最大基准统一规范为对称正方形边界：`CANVAS_NODE_MAX_BOUND = 420`（即 `maxWidth = 420, maxHeight = 420`）；
  - 常见目标比例的预设外框矩阵确立为：
    - `1:1`：`420px × 420px`（面积饱满，契约对称）；
    - `16:9`：`420px × 236px`（宽度拉满，高度等比）；
    - `9:16`：`236px × 420px`（高度拉满，宽度等比）；
    - `4:3`：`420px × 315px`；
    - `3:4`：`315px × 420px`。

### 2. 占位预拟合引擎（Pre-fitting Seam）

- 在节点创建、参数变更以及任务提交三处入口，统一通过极窄尺寸计算函数解析初始与占位外框：
  - **模式 A（纯配置驱动）**：读取当前上下文的 `size` 字符串（如 `1024x1024` 或 `16:9`），调用比例解析器映射至 `420` 基准框；
  - **模式 B（参考图驱动）**：在无显式目标尺寸但存在参考资源（图生图/参考生图）时，读取主参考图的 `naturalWidth` 和 `naturalHeight`，将其宽高比映射至 `420` 基准框；
  - **模式 C（手动拉大继承）**：若当前节点已有尺寸且用户未开启自由变形，提取 `maxEdge = Math.max(node.width, node.height)`，若 `maxEdge > 420`，则以 `maxEdge` 作为基准边界进行等比占位；
  - **模式 D（自由变形锁定）**：若节点标记了 `freeResize`，则 100% 维持当前 `node.width` 与 `node.height`。

### 3. 生成完成结算外框锁死机制（Frame Lock Settlement）

- 任务完成回调中，废除以往无视现状直接覆盖 `node.width / node.height` 的逻辑：
  - 当骨架屏已根据模式 A/B/C 完成过比例占位，且当前任务为首次生成结算时：
    - 检查真实图片比例与当前卡片比例的偏差率：`diff = Math.abs(ratioActual - ratioFrame) / ratioFrame`；
    - 若偏差率小于阈值（0.08，约 8%），判定为模型生成对齐误差，**严格锁定 `node.width` 与 `node.height` 不变**；
    - 图像标签统一以 `object-contain` 充满容器，既消除多余变形，又保证边缘零裁切；
  - 只有在先前由于工作流无任何尺寸信息而处于兜底正方形状态时，才执行一次带几何中心锁定的精准适配。

### 4. 衍生节点与已有素材再次生成规范 (Branching & Repeat Policy)

- **已有素材再次生成（Repeat / Branching 机制）**：
  - **资产保护原则**：已有素材的卡片（`status: "success"` 且包含有效媒体内容）作为历史创作成果，**100% 保持不动**，外框尺寸、位置、连线与素材内容一律安全冻结，严禁原地覆盖重写；
  - **派生新卡片**：点击面板中的再次生成按钮时，自动在原老节点正右侧（`x = sourceNode.x + sourceNode.width + 96`，垂直居中对齐）派生一个全新的独立节点，若右侧被占用则向下顺延避让；
  - **新配置尺寸初始化**：新派生节点的初始骨架屏尺寸严格按照**用户当前新配置的长宽比**，调用 `resolveSkeletonDimensions` 按 `420px` 标准对称基线进行初始化，不继承老节点曾被手动拉大过的特殊比例，确保新建节点规范统一；
  - **上游拓扑继承**：新节点自动复制并继承老节点的所有上游输入连线（如提示词、参考图输入源），确保创作上下文连贯；
  - **完成结算**：新节点任务完成后，同样执行 0 像素抖动外框锁死结算机制；
- **超分（Upscale）与裁剪（Crop）**：派生子节点时，以父节点的 `Math.max(node.width, node.height)` 作为子节点的最大外框上限，消除突兀膨胀。

## Testing Decisions

### 1. 优质测试的判别准则

- **仅测试外显行为与物理几何状态**：断言节点在关键生命周期钩子（创建、提交任务、完成结算、再次生成）上的 `width`、`height` 以及 `position`，不刺探组件内部的具体 style 计算过程；
- **全比例穷举覆盖**：涵盖 1:1、16:9、9:16、非标长宽比，以及不同上游来源（空白卡片、Config 节点派生、带参考图的图生图）；
- **用户干预保留验证**：针对用户手动拉大的节点，断言生成结算后尺寸严格保留或按用户最大边内切，绝不退化为系统默认值。

### 2. 测试接缝与测试集规划

- **核心集成接缝**：在 `web/src/lib/canvas/__tests__/canvas-node-size-lifecycle.test.ts` 中构建纯函数级完整生命周期测试矩阵；
- **参考先例**：遵循已有 [`canvas-generation-settlement.test.ts`](file:///Users/group/Documents/coder/claude_code/infinite-canvas/web/src/lib/canvas/__tests__/canvas-generation-settlement.test.ts) 与 [`canvas-node-factory.test.ts`](file:///Users/group/Documents/coder/claude_code/infinite-canvas/web/src/lib/canvas/__tests__/canvas-node-factory.test.ts) 的轻量、高确定性设计风格。

## Out of Scope

1. **画布之外的独立页面**：如素材库管理页、模型管理页等与无限画布无关的视图；
2. **底层 ComfyUI 模型出图尺寸干预**：本规范不修改 ComfyUI 模型工作流内部的生成分辨率，仅负责前端渲染、占位骨架与画布节点的几何契约管理；
3. **文本节点与音频节点的基本形态改变**：文本节点自适应正文排版，音频节点保持紧凑扁条（`340×120`），不在本次正方形基准改造范围内。
