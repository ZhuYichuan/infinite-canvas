# 0001. 预设资产索引在构建期固化，图片运行时按需取 CDN

- 状态：已采纳
- 日期：2026-11-02

## 背景

平台需要内置四套参考素材：线稿姿态（1439 张）、深度姿态（1439 张）、服装（1407 件）、发型人像（1499 件）。四套素材都已经以 Cloudflare Pages 站点形式公开托管，且响应头带 `access-control-allow-origin: *`。

但索引的形态各家不同：

- 姿态与服装是 `/index.json`，字段为日文键（`系統` / `分類` / `ポーズ名` / `アングル`）；
- 人像是 `/data/images.js`，一个挂到 `window.GALLERY_IMAGES` 的 JS 文件，不是 JSON；
- 服装索引的类目仍是日文，而提示词关键词是英文；
- 人像的发型类目是日文（`ショート` / `ミディアム` / `セミロング` / `ロング`），风格描述没有中文版本。

原始图片体量：姿态 1.2G、服装 2.6G（原寸）、人像 14G，且服装已有 512×768 与 1366×2048 两种规格分别落在不同站点。

## 决策

前端不直接消费这些远端索引。改由 `scripts/sync-system-presets.mjs` 在构建期拉取索引，结合仓库内维护的日→中对照表生成三份带中文字段的静态数据（`web/src/data/system-presets/*.json`）并入库。运行时前端只按 `id` 拼接 CDN 图片地址，索引不发起任何网络请求。

图片二进制一律不入库，也不做二次分发。

## 备选方案与取舍

**运行时直接 fetch 远端索引**：可热更新，但把首屏可用性绑在第三方站点的可用性与字段稳定性上；日文键与人像的 JS 格式仍需在运行时翻译，且无法静态校验字段。放弃。

**把图片一并入库/自建 CDN 再分发**：不受第三方变更影响，但 18G 素材与授权不确定性都放进了仓库。放弃。

**只在构建期抓取、不落库（构建时现场拉取）**：CI 每次构建依赖外网，任一 CDN 抖动就会让发布失败。放弃。

## 后果

- 索引离线可用、可静态校验、可被类型系统约束，三个 JSON 按类目懒加载，不进入首屏 bundle。
- CDN 新增资产不会自动出现在产品里：需要重跑同步脚本并提交 diff。`--check` 模式供 CI 检测漂移。
- 中文标签依赖 `scripts/system-presets/zh-labels.json` 与 `pose-names.zh.json`。出现未收录的日文键时同步脚本直接失败退出，而不是生成半成品数据。
- 第三方站点内容变化（下架、改路径、改授权）仍会以图片 404 或内容变更的形式影响产品，索引层无法兜底。
- 姿态的线稿与深度使用同一 `id` 命名空间，只有 host 与像素内容不同，因此建模为一个资产的两种 rendition，而非两类资产。
